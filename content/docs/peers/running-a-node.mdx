# Running a node

A Peers node lets two people behind ordinary home routers talk to each other. Both peers dial the node, reserve a circuit through it, and their messages flow. Then DCUtR hole-punches a direct connection and the node drops out of the path.

## Why run a node?

- Backbone infrastructure for cross-NAT communication
- Low resource usage: 10-20 MB RAM idle in headless mode
- Community contribution that strengthens the P2P network

## Prerequisites

- A VPS, Raspberry Pi, old laptop, or phone on a charger
- Public IP address (or ability to forward ports)
- Linux recommended (Ubuntu/Debian)

## Quick start

### 1. Build from source

```sh
# Install dependencies (Ubuntu/Debian)
sudo apt update
sudo apt install -y build-essential pkg-config \
    libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev \
    librsvg2-dev patchelf libxdo-dev libssl-dev

# Install Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
source ~/.cargo/env

# Clone and build
git clone https://github.com/PeersTech/Peers.git
cd Peers/backend
cargo build --release

# The binary is at target/release/peers
```

### 2. Configure the port

```sh
# Open firewall (TCP + UDP)
sudo ufw allow 4001/tcp
sudo ufw allow 4001/udp
```

### 3. Start the node

```sh
./peers --node
```

### 4. Verify

Look for these lines:

```
peers node peer id: 12D3KooW...
announcing: /ip4/203.0.113.7/tcp/4001/p2p/12D3KooW...
  -> PEERS_NODES=/ip4/203.0.113.7/tcp/4001/p2p/12D3KooW...
peers node is up.
reachability: public (peers dialed us successfully)
```

- public. Working.
- PRIVATE. Firewall issue. No clients can use this node.
- unknown. Not enough peers yet. Wait a few minutes.

## Client configuration

Point clients at your node by creating `config/peers/nodes.json`:

```json
["/ip4/203.0.113.7/tcp/4001/p2p/12D3KooW..."]
```

| Platform | Path |
|---|---|
| Linux | ~/.config/peers/nodes.json |
| macOS | ~/Library/Application Support/peers/nodes.json |
| Windows | %APPDATA%\peers\nodes.json |

Both people who want to talk must point at the same node.

## Systemd service

Create /etc/systemd/system/peers-node.service:

```ini
[Unit]
Description=Peers Relay Node
After=network.target

[Service]
Type=simple
User=peers
WorkingDirectory=/home/peers
ExecStart=/home/peers/peers --node
Restart=always
RestartSec=10
Environment=PEERS_PORT=4001

[Install]
WantedBy=multi-user.target
```

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now peers-node
```

## Environment variables

| Variable | Default | Description |
|---|---|---|
| PEERS_PORT | 4001 | Listen port (TCP + UDP) |
| PEERS_PUBLIC_IP | auto | Public IP for client dialing |
| PEERS_ANNOUNCE | none | Full multiaddr override (advanced) |
| PEERS_NODES | none | Upstream nodes to chain to |
| PEERS_NO_RELAY | none | Set to 1 to disable relaying |

## Troubleshooting

Node starts but no client can connect.

Check the reachability line. If PRIVATE, the port is not open. Check both ufw and cloud security groups.

Node exits with library error.

Missing webkit/GTK runtime libraries. Build from source or use the Pterodactyl egg.

peer connected but never relay reservation granted.

Node at capacity (64 reservations). Add a second node.
