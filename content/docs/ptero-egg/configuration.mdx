## Environment variables

| Variable | Default | Description |
|---|---|---|
| INSTALL_METHOD | source | source or release. See below. |
| PEERS_REF | pinned commit | Commit SHA to build. The installer refuses to build a different commit than the one pinned. |
| PEERS_REPO | `https://github.com/PeersTech/Peers.git` | Change only for a fork. |
| PEERS_RELEASE_SHA256 | none | Required with `INSTALL_METHOD=release`; SHA-256 of the exact `peers-linux-x86_64` asset from a trusted source. |
| RUSTUP_INIT_SHA256 | none | Required with `INSTALL_METHOD=source`; SHA-256 of `rustup-init`, published alongside the binary at `static.rust-lang.org`. The installer will not execute an unverified rustup. |
| PEERS_PUBLIC_IP | auto | The address clients dial. This is not authentication; the Directory API authenticates writes with the node's Ed25519 identity signature. |
| PEERS_ANNOUNCE | none | Full multiaddr override. Advanced. |
| PEERS_NODES | none | Upstream nodes to chain to. |
| PEERS_NO_RELAY | 0 | 1 forwards nothing. |
| CARGO_BUILD_JOBS | 2 | Lower to 1 if the install is OOM-killed. |

## Identity and panel access

Pterodactyl controls installation and the file manager; it is not a Peers
account system. The headless node's `node_identity.json` is its libp2p routing
identity and Directory API signing key. Do not put that file in egg variables,
startup commands, or public logs. The runtime container writes it below
`/home/container/.config/peers/` with `0600` permissions.

The Directory API needs no Pterodactyl password or API token. Its public read
and health routes are unauthenticated; registration uses the node's Ed25519
signature, and heartbeats use a signed timestamp.

## INSTALL_METHOD

### source (recommended)

Builds the node from the git repository. Slow (10-25 minutes) but always works.

`PEERS_REF` defaults to a pinned commit rather than a branch, so the same egg
installs the same reviewed code. If you set `PEERS_REF` to a full 40-character
commit SHA, the installer aborts when the clone resolves to anything else.

Source installs also require `RUSTUP_INIT_SHA256`. The installer downloads
`rustup-init` as a file, verifies it against that checksum, and refuses to
execute it otherwise:

```
RUSTUP_INIT_SHA256=$(curl -fsSL https://static.rust-lang.org/rustup/dist/x86_64-unknown-linux-gnu/rustup-init.sha256 | cut -d' ' -f1)
```

Supply it as an egg install variable. Piping `rustup.rs` straight into `sh`
would execute whatever the mirror served at that moment with no integrity
check at all.

### release

Downloads the exact `peers-linux-x86_64` asset from GitHub Releases. Release
mode is only available on Linux `x86_64` and requires
`PEERS_RELEASE_SHA256`, obtained from a trusted source. The installer verifies
the checksum before moving the binary into place. PeersTech/Peers has not
published that asset yet, so source remains the supported default.

## Build memory

Linking a Tauri binary is memory-hungry. If the install stops partway through with no error, it was OOM-killed. Either raise the server's memory limit for the duration of the install, or set CARGO_BUILD_JOBS=1.

A source build takes 10 to 25 minutes.

## Upstream nodes

The PEERS_NODES variable lets you chain nodes together. Each value must be a full multiaddr including the /p2p/peer-id suffix:

```
/ip4/203.0.113.7/tcp/4001/p2p/12D3KooW...
```

Multiple nodes can be comma-separated:

```
/ip4/203.0.113.7/tcp/4001/p2p/12D3KooW...,/ip4/198.51.100.3/tcp/4001/p2p/12D3KooX...
```

`PEERS_PUBLIC_IP` and automatic detection are IPv4-only in this egg. Use
`PEERS_ANNOUNCE` for IPv6 or DNS-based addresses, and verify that the upstream
node is actually listening on the transport you announce.

## Announce override

PEERS_ANNOUNCE allows full control over the multiaddr advertised to clients. Use this for:

- IPv6 addresses
- DNS names
- Different external/internal ports

Format: comma-separated multiaddrs without the /p2p/id suffix:

```
/ip4/1.2.3.4/tcp/4001,/ip4/1.2.3.4/udp/4001/quic-v1
```
