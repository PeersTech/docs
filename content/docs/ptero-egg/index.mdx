title: Pterodactyl egg

Runs an always-on Peers relay node as a Pterodactyl server.

A node is what lets two people behind ordinary home routers talk to each other. Both peers dial the node, reserve a circuit through it, and their messages flow. Then DCUtR hole-punches a direct connection and the node drops out of the path. It is a switchboard, not a bottleneck.

This egg requires a custom runtime image before the panel setup is complete.
For a native VPS or Raspberry Pi deployment, use the [native node guide](/docs/peers/running-a-node).

The node never decrypts sealed direct messages. It does process signed control
traffic and server-channel messages, so it can observe that metadata and
plaintext protocol content. Running one does not make you a trusted party for
the full protocol.

## Files

| File | What it is |
|---|---|
| egg-peers-node.json | Import this into the panel. Generated. Do not hand-edit. |
| install.sh | The install script. Source of truth. |
| egg.meta.json | Egg metadata and variables. Source of truth. |
| build-egg.sh | Regenerates the egg JSON from the two files above. |
| Dockerfile | Runtime image. You need to build and host this. |
| entrypoint.sh | Container entrypoint, baked into the image. |

After changing install.sh or egg.meta.json, run `./build-egg.sh` and re-import.
Start with [Setup](/docs/ptero-egg/setup), then review [Configuration](/docs/ptero-egg/configuration)
and keep [Troubleshooting](/docs/ptero-egg/troubleshooting) nearby.
