# Directory API

A Cloudflare Worker (Hono + D1) that answers "which backbone nodes are alive right now?" Clients find relay nodes without pasting addresses. Discovery only. No message traffic touches this.

Production URL: https://directory.peers.dpdns.org

## Purpose

When a user opens Peers, they need to find relay nodes to connect to. The Directory API maintains a registry of active nodes and serves them to clients on demand.

## Trust model

- A libp2p peer ID embeds its own Ed25519 public key. Every request is verified against the key inside the ID.
- The multiaddr must terminate at /p2p/same peer ID. Address poisoning is structurally impossible.
- Nonces are consumed atomically (DELETE ... RETURNING). Replays fail.
- Clients still dial-and-verify locally. A hostile directory can degrade onboarding, never read traffic.

## Scale

| Metric | Value |
|---|---|
| Write volume | 480k writes/day at 10k nodes |
| Storage | 10k rows is a rounding error for D1 |
| Heartbeat cadence | Adaptive (30 min default, grows with fleet) |
| Free tier fit | ~2k nodes |

## Tech stack

- Runtime: Cloudflare Workers
- Framework: Hono (HTTP)
- Database: Cloudflare D1 (SQLite)
- Crypto: @noble/curves (Ed25519)
- Testing: Vitest
