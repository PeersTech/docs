# Directory API

A Cloudflare Worker (Hono + D1) that answers "which backbone nodes are alive right now?" Nodes register with signed peer IDs and heartbeat to stay listed. Clients fetch the list instead of pasting addresses by hand.

Production URL: https://directory.peers.dpdns.org

## Status

The service is live and the protocol is stable. Peers clients do not call it yet. Today, operators copy the `PEERS_NODES=` line from `peers --node` and hand it to users by hand. The intended flow once wired: fetch `/v1/nodes`, use `peersNodes` as `PEERS_NODES` or split it on commas into `nodes.json`.

Peer discovery itself needs no directory. Finding *where a peer is* already works over the public IPFS DHT. This service solves the narrower problem: finding *relay nodes with public addresses* so two NAT'd peers have something to dial.

## Trust model

- A libp2p peer ID embeds its own Ed25519 public key. Every request is verified against the key inside the ID. No accounts, no trust on first use.
- Every multiaddr must terminate at `/p2p/<same peer id>` that signed. Address poisoning is structurally impossible.
- Nonces are consumed atomically (`DELETE ... RETURNING`). Replays fail.
- Clients still dial and verify locally. A hostile directory can degrade onboarding, never read traffic. There is no traffic here to read.

## Scale

| Metric | Value |
|---|---|
| Write volume | Heartbeats only, adaptive cadence (30 min default): 10k nodes is about 480k writes/day |
| Storage | 10k rows is a rounding error for D1 |
| Free tier fit | About 2k nodes |

## Tech stack

- Runtime: Cloudflare Workers
- Framework: Hono (HTTP)
- Database: Cloudflare D1 (SQLite)
- Crypto: @noble/curves (Ed25519)
- Testing: Vitest
