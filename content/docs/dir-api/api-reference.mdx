title: API reference
description: Endpoint documentation for the Directory API
---

All endpoints return JSON with `{ok: boolean, protocol: 1, ...}` and send an
`X-Peers-Protocol: 1` response header.

Every response carries `heartbeatAfterSec`. The service currently uses a fixed
30-minute heartbeat cadence. There is no bearer token or account system:
health and list reads are public, registration uses a signed single-use
challenge, and heartbeats use a signed timestamp.

Addresses are `multiaddrs`: comma-separated full multiaddrs, each ending in
`/p2p/<same peer id>`. The registry accepts IP4, IP6, DNS4, DNS6, and DNSADDR
hosts; DNSADDR entries have no explicit port, while the other forms must end in
`/tcp/<port>` or `/udp/<port>` (QUIC adds `/quic-v1`). That is the same format
as `PEERS_NODES`, so the list endpoint output drops straight into client config.

Tiers are the Peers relay tiers: `citizen`, `node`, or `off`. Anything else is rejected with 400. Absent means `node`. Nodes with `tier: "off"` are accepted for bookkeeping but omitted from relay discovery.

## Health check

```
GET /healthz
```

Response:

```json
{
  "ok": true,
  "protocol": 1,
  "heartbeatAfterSec": 1800,
  "nodes": 1234,
  "metrics": {
    "registeredNodes": 1234,
    "freshNodes": 987
  }
}
```

## Challenge

Get a single-use nonce for registration. Expires after 5 minutes. If the peer
already has an unexpired challenge, the service returns that existing nonce
instead of invalidating it with a new request.

```
GET /v1/challenge?peerId={peerId}
```

Parameters:

| Name | Type | Description |
|---|---|---|
| peerId | string | Base58-encoded libp2p peer ID |

Response:

```json
{
  "ok": true,
  "nonce": "a1b2c3d4e5f6...",
  "expiresInSec": 300
}
```

Errors:

- `400` — malformed peer id
- `429` — peer or source-IP request limit exceeded

## Register

Register a node with a signed challenge nonce. The nonce is consumed atomically, so each challenge works exactly once. Tier is checked before the nonce is consumed, so a bad tier does not burn a challenge.

```
POST /v1/register
```

Body:

```json
{
  "peerId": "12D3KooW...",
  "nonce": "a1b2c3d4e5f6...",
  "sig": "base64-ed25519-signature",
  "multiaddrs": "/ip4/203.0.113.7/tcp/4001/p2p/12D3KooW...,...",
  "region": "us-east-1",
  "tier": "node"
}
```

Signature message:

```
peers-directory:v1:register:{peerId}:{nonce}
```

The v1 registration proof binds the peer ID and nonce. The request metadata is
validated separately but is not included in the v1 signature.

Response:

```json
{
  "ok": true,
  "heartbeatAfterSec": 1800
}
```

Errors:

- `400` — body must be json
- `400` — peerId, nonce, sig required
- `400` — signature invalid
- `400` — tier must be citizen, node, or off
- `400` — nonce unknown, expired or already used
- `400` — multiaddrs must be comma-separated addrs ending in /p2p/same peer id

## Heartbeat

Keep a node alive. Inside half the configured cadence, this is a free ack
(write-skipped) rather than a write. Unknown nodes may bootstrap straight into
a heartbeat, but then they must supply addresses.

```
POST /v1/heartbeat
```

Body:

```json
{
  "peerId": "12D3KooW...",
  "ts": 1700000000000,
  "sig": "base64-ed25519-signature",
  "multiaddrs": "/ip4/203.0.113.7/tcp/4001/p2p/12D3KooW...,...",
  "region": "us-east-1",
  "tier": "node"
}
```

Signature message:

```
peers-directory:v1:heartbeat:{peerId}:{timestamp}
```

The timestamp must be within the skew window (15 minutes by default). This rejects
stale and future requests, but the v1 heartbeat proof does not provide durable
replay protection; keep the endpoint behind HTTPS and do not reuse a captured
request. The v1 signature also does not bind `multiaddrs`, `region`, or `tier`.

Response:

```json
{
  "ok": true,
  "heartbeatAfterSec": 1800
}
```

Or if write-skipped:

```json
{
  "ok": true,
  "skipped": true,
  "heartbeatAfterSec": 1800
}
```

Errors:

- `400` — signature invalid or clock too far off
- `400` — tier must be citizen, node, or off
- `400` — unknown node: multiaddrs ending in /p2p/id required

## List nodes

Get fresh (recently seen) nodes with keyset pagination. The `peersNodes` field is the whole page as one comma-joined string. Paste it directly as `PEERS_NODES`, or split on commas into `nodes.json`.

```
GET /v1/nodes?limit={limit}&cursor={cursor}
```

Parameters:

| Name | Type | Default | Description |
|---|---|---|---|
| limit | number | 200 | Max nodes per page (1-500) |
| cursor | string | none | Opaque pagination cursor from the previous response |

Response:

```json
{
  "ok": true,
  "protocol": 1,
  "heartbeatAfterSec": 1800,
  "peersNodes": "/ip4/203.0.113.7/tcp/4001/p2p/12D3KooW...,...",
  "nodes": [
    {
      "multiaddrs": "/ip4/203.0.113.7/tcp/4001/p2p/12D3KooW...,...",
      "peerId": "12D3KooW...",
      "lastSeen": 1700000000000,
      "region": "us-east-1",
      "tier": "node"
    }
  ],
  "nextCursor": "1700000000000:12D3KooW...",
  "directoriesHint": ["https://directory.peers.dpdns.org"]
}
```

Newest first. The cursor is a composite `lastSeen:peerId` pair, so rows sharing a timestamp never straddle or repeat across pages. `nextCursor` is present only when another page exists. Records with `tier: "off"` are omitted from this fresh relay list, while `/healthz` counts all stored rows.

Errors:

- `400` — `limit` must be an integer between 1 and 500
- `400` — `cursor` is invalid
