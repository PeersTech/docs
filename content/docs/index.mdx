Tools for decentralized communication. Peers has no central message server,
accounts, or project-operated message database. Direct messages are sealed
end-to-end between their peers; server-channel, Plaza, and relay-control
payloads are signed or plaintext protocol traffic and are not end-to-end
secrets. Optional relay nodes and a node directory make communication across
NATS possible.

## How it works

```text
graph TB
    subgraph Clients
        A[Peers App]
        B[Peers App]
    end

    subgraph P2P Network
        C[libp2p Mesh]
        D[Kademlia DHT]
        E[Gossipsub]
    end

    subgraph Relay Nodes
        F[Node 1]
        G[Node 2]
        H[Node N]
    end

    A -->|Sealed DMs| C
    B -->|Sealed DMs| C
    C --> D
    C --> E
    F --> C
    G --> C
    H --> C

    subgraph Manual Setup
        O[Operator copies PEERS_NODES line]
    end

    F --> O
    O --> A
    O --> B

    subgraph Directory
        I[Directory API]
    end

    F -->|Register + Heartbeat| I
    G -->|Register + Heartbeat| I
    H -->|Register + Heartbeat| I
    A -.-|Planned: fetch nodes| I
```

Peers find each other over the public IPFS DHT. That solves discovery. Relay nodes solve reachability: both NAT'd peers dial the same node, reserve a circuit, and exchange traffic. Direct-message envelopes remain sealed; the other gossipsub topics carry signed or plaintext protocol payloads. DCUtR then tries to upgrade the connection to a direct one.

Today, an operator copies the `PEERS_NODES=` line from `peers --node` and hands it to both users, who paste it into `PEERS_NODES` or `nodes.json`. The Directory API already accepts signed registrations and heartbeats from nodes. Client fetching is the planned next step, not yet wired. A relay node is not a privacy boundary for signed or plaintext server, Plaza, and control topics; see [the security model](/docs/peers/architecture).

## Design principles

- Self-certifying identities. Ed25519 keys embedded in peer IDs.
- Serverless by default. No canonical node list ships with Peers, since that would make those nodes a central dependency.
- NAT traversal through Circuit Relay v2 and DCUtR hole punching.
- Runs on Raspberry Pi, old laptops, and cheap VPSs. A node uses 30 to 60 MB of RAM.
